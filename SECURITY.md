# Security Policy

## Supported Versions

Only the latest release receives security updates. Please verify that the vulnerability exists on the latest release or on the `main` branch before submitting a report.

## Reporting a Vulnerability

**Please do not open a public issue or discussion for security vulnerabilities.**

Submit your report privately via GitHub:
1. Go to the **Security** tab of the repository.
2. Click **Policy** / **Report a vulnerability** (or use private vulnerability reporting).

This report will only be visible to project maintainers. To help us handle it efficiently, please include:

- The affected version or commit hash.
- A description of the vulnerability and its potential impact.
- The conditions required to exploit it (e.g., local network access, specific configuration, PIN enabled).
- Step-by-step instructions to reproduce the issue, a proof of concept (PoC), or a patch if available.

### What to Expect

- **Response time:** You will receive an acknowledgment as soon as possible. As this project is maintained on free time, please allow a few days for a reply.
- **Resolution & Attribution:** Once a fix is released, a public advisory will be published, and you will be credited for the discovery (unless you prefer to remain anonymous).
